[Shelve](https://shelve.cloud) stores a team's environment variables per project and environment. With this integration, the build fetches them, merges them into `runtimeConfig`, and then validates the result against your schema.

## Setup

::steps

### Store your secrets in Shelve

Create a team and a project at [app.shelve.cloud](https://app.shelve.cloud), or push an existing `.env`:

```bash
pnpm add -D @shelve/cli
shelve login
SHELVE_PROJECT=my-app SHELVE_TEAM_SLUG=my-team shelve push
```

### Enable the integration

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['nuxt-safe-runtime-config'],
  safeRuntimeConfig: {
    $schema: runtimeConfigSchema,
    shelve: {
      project: 'my-app',
      slug: 'my-team',
    },
  },
})
```

`shelve: true` also works when `SHELVE_PROJECT` and `SHELVE_TEAM` are set, or the project is named after `package.json`. An object without `project`, `slug`, `team` or `enabled: true` leaves the integration off.

### Provide a token

Locally, `shelve login` stores a token in `~/.shelve`, and the module reads it. In CI, set `SHELVE_TOKEN` from a [user token](https://app.shelve.cloud/user/tokens).

::

`nuxi module add nuxt-safe-runtime-config` offers to do these steps in an interactive terminal. It lists what it will change (install a schema library, write `~/.shelve`, edit `nuxt.config`) and asks before applying it. It does not run in CI.

## What happens at build

1. The module resolves project, team, environment and token.
2. It fetches the environment's variables from the Shelve API.
3. It maps each variable name to a runtime config path (see below).
4. It merges them into `runtimeConfig`. Shelve values win over `nuxt.config.ts`.
5. Build validation, when on, runs on the merged config.

If the API request fails, the build fails with `onError: 'throw'` and logs an error otherwise. If the project, team or token cannot be resolved, the module logs a warning and builds without Shelve values. Validation then reports the missing keys.

Secrets fetched at build are written into the server bundle. Use runtime fetch if that is not acceptable.

## Variable names

Shelve variables are `SCREAMING_SNAKE_CASE`. They map to runtime config like this:

```txt
DATABASE_URL          → databaseUrl
GITHUB_CLIENT_ID      → github.clientId
GITHUB_CLIENT_SECRET  → github.clientSecret
STRIPE_KEY            → stripeKey
NUXT_PUBLIC_API_BASE  → public.apiBase
PUBLIC_SITE_NAME      → public.siteName
```

- `NUXT_PUBLIC_` and `PUBLIC_` prefixes go under `public`.
- Two or more variables that share their first word are grouped under it: `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET` become `github.clientId` and `github.clientSecret`. A prefix used once, like `STRIPE_`, is not grouped.
- The rest becomes camelCase.

Write the schema for the mapped shape.

## Fetch at runtime

To keep secrets out of the build, fetch them when the server starts:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  safeRuntimeConfig: {
    $schema: runtimeConfigSchema,
    validateAtRuntime: true,
    shelve: {
      project: 'my-app',
      slug: 'my-team',
      fetchAtBuild: false,
      fetchAtRuntime: true,
    },
  },
})
```

The build needs no token. The server reads `SHELVE_TOKEN` when it starts and fetches the variables. Requests wait until the fetch finishes. The secrets are merged into runtime config, taking priority over `NUXT_*` values, and runtime validation checks the merged result. `useSafeRuntimeConfig()`, `useSafeRuntimeConfig(event)` and `useRuntimeConfig(event)` all return them.

If the server has no `SHELVE_TOKEN`, or the request to Shelve fails, it logs the problem and continues without Shelve values. Runtime validation then reports the missing keys.

## Options

::field-group
  ::field{name="project" type="string"}
  Shelve project name. Falls back to `SHELVE_PROJECT`, then the `package.json` name.
  ::

  ::field{name="slug" type="string"}
  Team slug. `team` is an alias. Falls back to `SHELVE_TEAM`, then `SHELVE_TEAM_SLUG`.
  ::

  ::field{name="environment" type="string"}
  Shelve environment. Falls back to `SHELVE_ENV`, then `development` in `nuxt dev` and `production` otherwise.
  ::

  ::field{name="url" type="string" default="'https://app.shelve.cloud'"}
  API URL for a self-hosted Shelve. Falls back to `SHELVE_URL`.
  ::

  ::field{name="fetchAtBuild" type="boolean" default="true"}
  Fetch during `nuxt dev` and `nuxt build`.
  ::

  ::field{name="fetchAtRuntime" type="boolean" default="false"}
  Fetch when the server starts. Needs `SHELVE_TOKEN` in the server environment.
  ::

  ::field{name="enabled" type="boolean"}
  Turn the integration on without other options, or off while keeping them.
  ::
::

The token comes from `SHELVE_TOKEN`, then `~/.shelve`. It cannot be set in `nuxt.config.ts`.
