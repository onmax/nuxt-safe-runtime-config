`envSchema` reads a `.env.example` written in the `env-spec-v1` profile: the [@env-spec syntax](https://varlock.dev/env-spec/reference/) with a small set of [Varlock decorators](https://varlock.dev/reference/item-decorators/). It is not the full Varlock runtime. The file declares names, types, descriptions, defaults, and whether each value is required and public. It never reads `.env`, fetches secrets or evaluates expressions.

```dotenv [.env.example]
# @defaultRequired=true @defaultSensitive=true
# ---

# Database connection supplied by the deployment.
# @type=url @example="https://database.example.test"
NUXT_DATABASE_URL=

# @type=number(min=1, max=65535, isInt=true)
NUXT_SMTP_PORT=587

# @type=enum(debug, info, warn, error) @public
NUXT_PUBLIC_LOG_LEVEL=info

# @optional @public
NUXT_PUBLIC_BANNER=
```

[.env.example as schema](/guide/env-schema) shows how the module maps these entries to runtime config.

## Header

An optional header sets defaults for every entry and ends with `# ---`. It accepts two decorators, both `true` by default:

| Decorator | Meaning |
| --- | --- |
| `@defaultRequired=false` | Entries are optional unless marked `@required` |
| `@defaultSensitive=false` | Entries are public unless marked `@sensitive` |

## Entries

A name matches `[A-Za-z_][A-Za-z0-9_]*` and is at most 256 characters. Duplicate names fail, and so do `__proto__`, `prototype` and `constructor` in any case.

The comment lines right above an entry become its description. A blank line or a divider ends it, and a comment that looks like a disabled assignment, such as `# OLD_KEY=1`, is left out. Decorators can share a comment line.

| Decorator | Meaning |
| --- | --- |
| `@type=…` | The value's type. See [Types](#types). Without it, the value is a string. |
| `@required`, `@required=false` | The value must be present and not empty. |
| `@optional`, `@optional=false` | The inverse of `@required`. Use one or the other. |
| `@sensitive`, `@sensitive=false` | The value must stay private. |
| `@public`, `@public=false` | The inverse of `@sensitive`. Use one or the other. A key still needs the `NUXT_PUBLIC_` prefix to reach the browser. |
| `@example="sample"` | Documentation. It never becomes a default. |

A repeated decorator, an unknown one, or a conflicting pair such as `@required @optional` fails with the file and line.

## Types

| `@type` | Value |
| --- | --- |
| `string` | A string. Optional bounds: `string(minLength=1, maxLength=80)`. |
| `number` | A finite number. Optional bounds: `number(min=0, max=100, isInt=true)`. |
| `boolean` | `true` or `false`. |
| `enum(debug, info, error)` | One of the listed strings. Quote a choice that looks like a number or a boolean. |
| `url` | An absolute URI, checked with the JSON Schema `uri` format. The value stays a string. |
| `array`, `array(string)` | A JSON array, with an optional item type. |
| `object`, `object(enabled=boolean, retries=number)` | A JSON object. With properties, it must have exactly those. Bare `object` accepts any JSON object, and `object()` only an empty one. |

Types nest, as in `array(object(name=string, roles=array(enum(read, write))))`, up to 16 levels.

The assigned value never sets the type. `TOKEN=00123` and `FLAG=true` are both strings unless `@type` says otherwise.

## Defaults

| Written as | Means |
| --- | --- |
| `KEY=value` | `value` is the default |
| `KEY=` | No default |
| `KEY=""` | The default is an empty string |
| `KEY='["read"]'` | A JSON default for an array or object, in quotes |

This is stricter than the usual tools. [dotenv-safe](https://www.npmjs.com/package/dotenv-safe) treats example values as documentation, and dotenv reads `KEY=` as an empty string. Here an assigned value ships as a real default, so a placeholder like `changeme` belongs in `@example`.

Each default is checked against its type when the module reads the file, and a bad one fails with the file, line and key:

| Type | Accepted default |
| --- | --- |
| `string` | Anything. It keeps its exact content, including leading zeros and whitespace inside quotes. |
| `number` | Decimal notation, with exponents. Not hexadecimal, `NaN` or `Infinity`. Surrounding whitespace is trimmed. |
| `boolean` | `true`, `false`, `1` or `0`. Surrounding whitespace is trimmed. |
| `enum` | One of the listed choices. |
| `url` | A URI exactly as written, with no surrounding whitespace. Use Punycode for international hostnames, such as `https://xn--r8jz45g.xn--zckzah` for `https://例え.テスト`, and percent-encode spaces and non-ASCII path characters. The same rule applies at server start. |
| `array`, `object` | Quoted JSON whose members already match their types. Members are never converted, so `"false"` fails a `boolean` property. |

## Empty values

On a required entry, `KEY=""` fails when the module reads the file, and an empty value at server start fails validation. An optional string keeps `""`. For any other optional type, empty means unset, so starting the server with `NUXT_REQUEST_LIMIT=` for an `@optional @type=number` entry gives `undefined`.

## Rejected syntax

The module rejects anything it can't check statically, instead of declaring a type it can't enforce:

- `$VAR` and `${VAR}` references. Single quotes or `\$` make them literal text.
- `$(command)` substitutions and calls such as `fetchSecret(ref)`
- unquoted `[a, b]` and `{key=value}` values. Quote JSON defaults instead.
- dynamic decorator values such as `@required=forEnv(production)`
- custom types and unknown type arguments
- JSON nested deeper than 64 levels, and the keys `__proto__`, `prototype`, `constructor` and `__envSchemaUnset` in any JSON object

Error messages give the file, line, key and reason. They never include an assigned value.
