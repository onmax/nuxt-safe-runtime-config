---
title: Schema libraries
description: Use any Standard Schema library for $schema.
navigation.icon: i-ph-brackets-curly
---

`$schema` accepts any library that implements [Standard Schema](https://standardschema.dev/). The module validates through the shared `~standard` interface, so switching libraries means rewriting the schema, not the config.

::code-group

```ts [Valibot]
import * as v from 'valibot'

const schema = v.object({
  apiKey: v.string(),
  port: v.optional(v.number()),
})
```

```ts [Zod]
import { z } from 'zod'

const schema = z.object({
  apiKey: z.string(),
  port: z.number().optional(),
})
```

```ts [ArkType]
import { type } from 'arktype'

const schema = type({
  'apiKey': 'string',
  'port?': 'number',
})
```

::

Build validation runs your library as written. For runtime validation and generated types, an inline schema is converted to JSON Schema, so it must use features JSON Schema can express. Transforms, custom refinements and other code-only checks belong in a [schema module](/guide/environment-overrides#transform-values-with-a-schema-module), which the server runs as written.
