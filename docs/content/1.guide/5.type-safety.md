`useRuntimeConfig()` infers its types from the defaults in `nuxt.config.ts`, which is wrong in three common cases:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  runtimeConfig: {
    apiSecret: '', // typed string, even when production never sets it
    sampleRate: 0, // typed number, but on Nitro 3 NUXT_SAMPLE_RATE=0.5 arrives as '0.5'
    // sentryDsn has no default, so it doesn't exist in the types at all
  },
})
```

`useSafeRuntimeConfig()` takes its types from the schema instead. You don't pass a generic, in components, plugins, `server/api` or `server/utils`:

```ts
const config = useSafeRuntimeConfig()
config.public.apiBase // string
config.port // number | undefined, from optional(number())
config.missingKey // type error
```

## Where the types come from

During `nuxt prepare` and `nuxt dev`, the module writes `.nuxt/types/safe-runtime-config.d.ts` and adds it to the app and server TypeScript projects. For the schema on the [Installation](/guide/installation) page it contains:

```ts [.nuxt/types/safe-runtime-config.d.ts]
export type SafeRuntimeConfig = {
  databaseUrl: string
  public: {
    apiBase: string
    replayEnabled: boolean
  }
}
```

How it builds that type depends on the schema source:

| Schema source | Type |
| --- | --- |
| Inline `$schema` | Converted to JSON Schema, then to TypeScript |
| A schema module, `$schema: './file'` | The schema's output type |
| `envSchema` | Each entry's `@type`, whether it's required, and whether it's public |

The server runs a schema module's transforms when it starts, so `NUXT_ALLOWED_ORIGINS=a.com,b.com` reaches your code as the array the schema produces. With the deprecated `validateAtRuntime: false`, the transforms never run and the type is the schema's input type.

After you change the schema, run `nuxi prepare` or restart `nuxt dev`. Don't edit the generated file.

## When the types lie

The types describe a config that passed validation. Two cases break that:

- With `onError: 'warn'` or `'ignore'`, a failed check still returns the raw config, untransformed, under the output type. Keep the default `'throw'` wherever you rely on the types.
- In the browser, Nuxt only ships `public`. Private keys are in the type and `undefined` at runtime, so read them in `server/`:

```ts [server/utils/mailer.ts]
export function createMailer() {
  const { smtp } = useSafeRuntimeConfig()
  return createTransport(smtp)
}
```

`useRuntimeConfig()` keeps the types Nuxt gives it. The [ESLint rule](/guide/eslint) finds the calls to move.
