`useRuntimeConfig()` returns whatever ends up in runtime config, which is the defaults in `nuxt.config.ts` replaced by any `NUXT_*` environment variable set when the server starts. Nothing checks that `NUXT_DATABASE_URL` is set, that `NUXT_PORT` is a number, or that `NUXT_PUBLIC_REPLAY_ENABLED=false` arrives as `false` instead of the string `'false'`. The types come from the defaults, so a secret that defaults to `''` is typed `string` even when production never sets it.

This module puts a schema on runtime config. It validates the values when you build or when the server starts, and `useSafeRuntimeConfig()` returns them typed from that schema.

```ts [server/api/report.post.ts]
export default defineEventHandler((event) => {
  const config = useSafeRuntimeConfig(event)
  config.databaseUrl // string
  config.public.replayEnabled // boolean, also when the server starts with NUXT_PUBLIC_REPLAY_ENABLED=false
})
```

## Choose a schema source

Each app uses one of the two.

::card-group
  :::card
  ---
  icon: i-ph-brackets-curly
  title: Standard Schema
  to: /guide/installation
  ---
  Set `$schema` to a Valibot, Zod or ArkType schema. Use it when you already use one of these libraries, or need transforms, unions or cross-field rules.
  :::

  :::card
  ---
  icon: i-ph-file-text
  title: .env.example (experimental)
  to: /guide/env-schema
  ---
  Set `envSchema` to a committed `.env.example` with `@type` annotations. Use it when every value comes from the deployment environment and builds must run without secrets.
  :::
::

## Choose when to validate

| You deploy | Validate | Option |
| --- | --- | --- |
| The values written in `nuxt.config.ts`, unchanged | at build | default |
| Values injected as `NUXT_*` variables when the server starts | at runtime | `validateAtRuntime: true` |
| Real values at build time and possibly different ones at runtime | both | `validateAtBuild: true` and `validateAtRuntime: true` |

[Validation](/guide/validation) explains each mode and what a failure does.

## What the module adds

- `useSafeRuntimeConfig()` and `useSafeRuntimeConfig(event)`, auto-imported in the app and in `server/`
- generated types in `.nuxt/types/safe-runtime-config.d.ts`
- an [ESLint rule](/integrations/eslint) that flags untyped `useRuntimeConfig()` calls
- a [Nitro module](/guide/nitro) for Nitro apps without Nuxt

## Compatibility

Nuxt 3 and 4 are supported. CI also runs Nuxt 4.2+ with `future.compatibilityVersion: 5` and the Nuxt 5 nightly channel (`nuxt-nightly@5x`). Validation runs on Nitro 2 (`nitropack` 2.13+) and Nitro 3.

On Nuxt 5, prefer [ViteHub Env](/guide/migrate-to-vitehub-env). The module still works there, and one command migrates an app.

The `.env.example` source needs Node.js 22 or later during `nuxt prepare` and `nuxt build`.
