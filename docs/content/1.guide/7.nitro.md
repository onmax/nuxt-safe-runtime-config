title: Nitro without Nuxt
description: Validate runtime config in a standalone Nitro app.

Validation itself lives in a Nitro module, which the Nuxt module wraps. A Nitro app without Nuxt can use it directly, with Nitro 2 (`nitropack`) or Nitro 3.

```ts [nitro.config.ts]
import safeRuntimeConfig from 'nuxt-safe-runtime-config/nitro'
import * as v from 'valibot'

export default defineNitroConfig({
  modules: [safeRuntimeConfig],
  runtimeConfig: {
    databaseUrl: '',
  },
  safeRuntimeConfig: {
    $schema: v.object({
      databaseUrl: v.pipe(v.string(), v.url()),
    }),
    validateAtRuntime: true,
  },
})
```

`safeRuntimeConfig` takes `$schema`, `validateAtBuild`, `validateAtRuntime`, `onError` and `jsonSchemaTarget`, with the same defaults as in Nuxt. A string `$schema` is resolved from the Nitro root.

What differs from Nuxt:

- `useSafeRuntimeConfig()` is not registered. With runtime validation on, the validated values are written into `useRuntimeConfig(event)` on Nitro 2 and into `useRuntimeConfig()` on Nitro 3. Nitro 2's shared `useRuntimeConfig()` is frozen and keeps the raw values.
- The generated types are written to `<buildDir>/types/safe-runtime-config.d.ts` and declare a global `NuxtSafeRuntimeConfig` interface.
- `envSchema` and Shelve are Nuxt-only.
