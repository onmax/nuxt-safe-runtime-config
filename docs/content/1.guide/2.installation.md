This page takes you from install to a typed config and a failing check. It uses Valibot; the [schema pages](/schemas) show the same schema in Zod and ArkType.

::steps

### Install the module

```bash
npx nuxi module add nuxt-safe-runtime-config
```

Install your schema library too if the app does not have one yet:

```bash
pnpm add valibot
```

### Add the schema

Describe every key you keep in `runtimeConfig`, including `public`:

```ts [nuxt.config.ts]
import * as v from 'valibot'

export default defineNuxtConfig({
  modules: ['nuxt-safe-runtime-config'],
  runtimeConfig: {
    databaseUrl: 'postgresql://localhost:5432/app',
    public: {
      apiBase: 'https://api.example.com',
    },
  },
  safeRuntimeConfig: {
    $schema: v.object({
      databaseUrl: v.pipe(v.string(), v.url()),
      public: v.object({
        apiBase: v.pipe(v.string(), v.url()),
      }),
    }),
  },
})
```

### Read the config

`useSafeRuntimeConfig()` is auto-imported in components, plugins and `server/`:

```vue [app.vue]
<script setup lang="ts">
const config = useSafeRuntimeConfig()
// config.public.apiBase: string
</script>
```

In server handlers, pass the event, as you would to `useRuntimeConfig(event)`:

```ts [server/api/health.get.ts]
export default defineEventHandler((event) => {
  const { databaseUrl } = useSafeRuntimeConfig(event)
  return checkDatabase(databaseUrl)
})
```

### Break it on purpose

Change `apiBase` to `'not a url'` and run `nuxt dev`. Startup stops with:

```txt
[safe-runtime-config] Validation failed!
  1. public.apiBase: Invalid URL: Received "not a url"
```

The wording of each issue comes from your schema library.

::

## Deploying with environment variables

The check above runs against `nuxt.config.ts`. If production sets `NUXT_DATABASE_URL` or `NUXT_PUBLIC_API_BASE` when the server starts, the build never sees those values. Turn on runtime validation:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  safeRuntimeConfig: {
    $schema: runtimeConfigSchema,
    validateAtRuntime: true,
  },
})
```

The server then validates the values it starts with, and the build stops checking the placeholders in `nuxt.config.ts`. [Validation](/guide/validation) covers the trade-off.

::tip
If your editor type-checks a file outside Nuxt's auto-imports, import the composable from `#imports`:

```ts
import { useSafeRuntimeConfig } from '#imports'
```
::
