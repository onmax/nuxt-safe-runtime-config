`useRuntimeConfig()` infers its types from the defaults in `nuxt.config.ts`. A key you never gave a default does not exist in the types, a default of `''` makes it a `string` even when production leaves it unset, and a `0` default makes `NUXT_RATE=0.5` look like a `number` when it can arrive as a string.

`useSafeRuntimeConfig()` is typed from the schema instead:

```ts
const config = useSafeRuntimeConfig()
config.public.apiBase // string
config.port // number | undefined, from optional(number())
config.missingKey // type error
```

No generic is needed, in components, plugins, `server/api` or `server/utils`.

## Where types come from

| Schema source | Generated type |
| --- | --- |
| Inline `$schema` | Converted to JSON Schema, then to a TypeScript type |
| Schema module (`$schema: './file'`) | The schema's input type, or its output type when `validateAtRuntime` is on |
| `envSchema` | The declared `@type`, requiredness and visibility of each entry |

Schema modules switch types because the transform only runs at runtime. Without runtime validation, an override such as `NUXT_PERF_TRACE_ENABLED=true` reaches your code untransformed, so the type is what the schema accepts. With runtime validation, the generated type describes the schema's output after successful validation.

If validation fails with `onError: 'warn'` or `'ignore'`, `useSafeRuntimeConfig()` returns the raw config without applying transforms, even though the generated type still describes the schema's output. Keep `onError: 'throw'` (the default) to prevent invalid values from being returned under that output type.

The declarations are written to `.nuxt/types/safe-runtime-config.d.ts` and included in the app and server TypeScript projects. Run `nuxi prepare` or restart `nuxt dev` after changing the schema. Never edit the generated file.

## Server and client

On the server, `useSafeRuntimeConfig()` returns the whole config. In the browser, Nuxt only ships `public`, so private keys are `undefined` at runtime even though the type lists them. Read private keys in `server/` only.

```ts [server/utils/mailer.ts]
export function createMailer() {
  const { smtp } = useSafeRuntimeConfig()
  return createTransport(smtp)
}
```

## useRuntimeConfig keeps its types

The module does not change the types of `useRuntimeConfig()`. Use the [ESLint rule](/integrations/eslint) to move call sites over to `useSafeRuntimeConfig()`.
