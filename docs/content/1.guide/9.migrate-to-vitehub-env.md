On Nuxt 5, use [ViteHub Env](https://vitehub.dev/docs/env) (`@vite-hub/env`) instead of this module. You still declare each value once and read it typed. What changes:

- **One API for Nuxt, Vite and Nitro.** Server code reads `useServerEnv(event)` and app code reads `usePublicEnv()`.
- **Secrets stay sealed.** A secret is a `SecretEnv` that prints as `<redacted>` until you call `.unseal()`.
- **The same `.env.example`.** Env reads the same [`env-spec` profile](/guide/env-schema), so an `envSchema` app moves without changes to the file.
- **Inspection from the CLI.** `vitehub env check` lists every declared variable and its status, and never prints values.

## Run the codemod

::steps

### Preview the changes

```bash
npx @vite-hub/codemods nuxt-safe-runtime-config --dry-run
```

`--dry-run` prints the diff of every file and a report, and writes nothing.

### Apply them

```bash
npx @vite-hub/codemods nuxt-safe-runtime-config
```

Pass a directory as the last argument when the app is not in the current directory.

### Install and check

```bash
pnpm install
npx nuxi prepare
```

Then type-check the app and work through the follow-ups in the report.

::

## What it changes

In `nuxt.config.ts`, the codemod replaces `nuxt-safe-runtime-config` with `vite-hub/nuxt` in `modules`. It moves the declarations to `vitehub.env` and removes `safeRuntimeConfig`. `package.json` drops this module and adds `vite-hub`.

### With `envSchema`

The `.env.example` stays as it is. `prefix: 'NUXT_'` keeps the same variable names and the same `public` split.

```ts [nuxt.config.ts]
import { envSchema } from '@vite-hub/env/vite'

export default defineNuxtConfig({
  modules: ['vite-hub/nuxt'],
  vitehub: {
    preset: 'node',
    env: envSchema(new URL('./.env.example', import.meta.url), { prefix: 'NUXT_' }),
  },
})
```

### With `$schema`

The codemod loads your schema, converts it to JSON Schema, and writes one Env declaration per value. Each value keeps its `NUXT_*` variable name, and literal defaults stay.

::code-group

```ts [Before]
export default defineNuxtConfig({
  modules: ['nuxt-safe-runtime-config'],
  runtimeConfig: {
    apiSecret: '',
    maxRetries: 3,
    featureEnabled: false,
    public: { apiBase: 'https://api.example.com' },
  },
  safeRuntimeConfig: {
    $schema: v.object({
      apiSecret: v.pipe(v.string(), v.minLength(16)),
      maxRetries: v.number(),
      featureEnabled: v.boolean(),
      public: v.object({ apiBase: v.pipe(v.string(), v.url()) }),
    }),
    validateAtRuntime: true,
  },
})
```

```ts [After]
import { env } from 'vite-hub/env'

export default defineNuxtConfig({
  modules: ['vite-hub/nuxt'],
  vitehub: {
    preset: 'node',
    env: {
      public: {
        apiBase: env({ default: 'https://api.example.com', mode: 'build', source: env.source('NUXT_PUBLIC_API_BASE') }),
      },
      server: {
        apiSecret: env({ secret: true, source: env.source('NUXT_API_SECRET') }),
        maxRetries: env.number({ default: 3, source: env.source('NUXT_MAX_RETRIES') }),
        featureEnabled: env.boolean({ default: false, source: env.source('NUXT_FEATURE_ENABLED') }),
      },
    },
  },
})
```

::

Server fields with credential-like names (`secret`, `token`, `password`, `key`, database URLs) become `secret: true`.

### In your code

```ts [server/api/config.get.ts]
// Before
const config = useSafeRuntimeConfig(event)

// After
import { useServerEnv } from '#vitehub/env/server'
const config = useServerEnv(event)
```

In app code, `useSafeRuntimeConfig()` becomes `usePublicEnv()` from `#vitehub/env/public`, and `config.public.apiBase` becomes `config.apiBase`.

## Follow-ups

The report lists each change the codemod could not make, with `file:line`:

- **Secret reads.** `config.apiSecret` is now a `SecretEnv<string>`. Call `.unseal()` where the code needs the raw value.
- **Lost checks.** Code-first Env declarations do not keep minimum lengths, patterns, URL formats, transforms or refinements. Check those values in code, or move to a `.env.example` with `envSchema()`, which keeps length, range, integer and URL checks.
- **JSON arrays, objects and unions.** These stay in `runtimeConfig`. Read them with `useRuntimeConfig()`, or declare them in a `.env.example`.
- **The deployment preset.** `vite-hub/nuxt` needs one. The codemod copies `nitro.preset` when it can, and otherwise sets `node`.
- **Call sites it did not rewrite.** For example, a config object passed to another function, or `useRuntimeConfig()` reads of keys that moved.
- **The ESLint rule.** Remove `nuxt-safe-runtime-config/eslint` from your ESLint config.

::warning
Public Env values are fixed at build time. Nuxt applied `NUXT_PUBLIC_*` overrides when the server started; with Env, set them before you build. Server Env values are still read when the server runs.
::

Shelve and the [standalone Nitro module](/guide/nitro) are not part of the codemod.
